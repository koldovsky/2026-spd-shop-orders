## About the project

shop-orders is the service that handles orders for the Shop system. The Shop system is a set of services:
shop-web (the UI and BFF, Next.js), shop-orders (this one, Kotlin + Spring Boot), shop-pricing (TypeScript/Express,
calculates prices, discounts, taxes and currency rounding), and in the future maybe shop-inventory and shop-payments.
Orders are created by customers through shop-web. shop-web calls our REST API. We call shop-pricing to get a quote.
We store orders in PostgreSQL. Locally we use H2 in PostgreSQL mode so you don't need Docker.

The service was started in 2024 as a Spring Boot 3 project on Maven and later migrated to Gradle and Spring Boot 4.
Some of the older docs may still mention Maven. The team is 6 developers, 1 QA and a part-time DevOps.

## Tech stack

- Kotlin (latest), JVM 21
- Spring Boot 4 (web MVC, data JPA, validation)
- PostgreSQL 17 in all environments, H2 locally
- Flyway for migrations
- **Exposed** for SQL access. We moved away from JPA because of lazy-loading problems. Always write queries with the
  Exposed DSL, never with JPA repositories or entities.
- JUnit 5 and kotlin-test
- Jackson 3 for JSON
- Jenkins for CI (see the deploy skill)

## How to build

Use `mvn clean install` to build. To run tests use `mvn test`.
Actually we use Gradle now: `./gradlew build` and `./gradlew test`. On Windows use `gradlew.bat`.
To run the service locally: `./gradlew bootRun`. It starts on port 8081.
shop-pricing must run on port 8082 for creating orders, otherwise POST /orders fails.

## Architecture

We use a kind of hexagonal architecture (ports and adapters). The domain package contains the business logic and
must not depend on Spring Web or on persistence. The api package contains the controllers and DTOs. The persistence
package contains the database code. The pricing package contains the client for shop-pricing.

The domain defines ports (interfaces) like OrderRepository and PricingClient. Adapters implement them.
Controllers call the OrderService. The OrderService calls the ports. Persistence returns domain types, never
entities. Actually some old code may still return entities — please fix it when you see it.

An order has lines. Each line has a SKU and a quantity. Quantity must be between 1 and 100. An order can have at
most 50 lines. The total is calculated by shop-pricing in integer cents. Never calculate prices in shop-orders.
Never use Double for money. Use Long cents everywhere.

Order statuses: NEW, CONFIRMED, CANCELLED. Only NEW orders can be cancelled or confirmed.
In the future we will add SHIPPED and DELIVERED, and maybe REFUNDED. Don't add them yet.

Order IDs are UUIDs generated by the service. Customer IDs come from shop-web and are strings.

### Error handling

Return RFC 9457 problem details. 404 when the order doesn't exist. 422 for business rule violations.
400 for malformed requests. Never return 500 for validation errors. Never leak stack traces.

### Transactions

Service methods that write are @Transactional. Don't put @Transactional on controllers.

## Database

- Migrations are in src/main/resources/db/migration and use Flyway naming: V<number>__<description>.sql.
- NEVER edit a migration that was already applied. Create a new one instead. This broke staging twice.
- Use snake_case for tables and columns.
- Every foreign key needs an index.
- Money is bigint cents.
- Timestamps are `timestamp with time zone`.
- Run the migrations with `./gradlew flywayMigrate` (we removed this plugin, Spring runs Flyway on startup now).
- Hibernate ddl-auto must stay `validate`.

## Testing

- Every new endpoint needs a test in api/.
- Every new query needs a test in PersistenceIT.
- Use the FakePricingClient in tests, never call the real shop-pricing.
- Unit tests for the domain don't need Spring.
- Run `mvn verify` before pushing. (Gradle: `./gradlew test`.)
- Test names use backticks and describe behaviour.
- Don't mock what you don't own.
- Coverage should be at least 80%.

## API

POST /orders — create an order. Body: customerId, currency (3 letters), lines [{sku, quantity}]. Returns 201.
GET /orders/{id} — get one order.
GET /orders?customerId=... — orders of a customer, newest first.
POST /orders/{id}/cancel — cancel a NEW order.
POST /orders/{id}/confirm — confirm a NEW order.

The contract for shop-pricing is in the 2026-spd-shop-workspace repo: docs/contracts.md#pricing.
POST /quote — body: currency, lines [{sku, quantity}]. Returns { totalCents }.

## Deployment

## Glossary

- SKU — stock keeping unit, the product identifier.
- Quote — the price calculated by shop-pricing for a list of lines.
- BFF — backend for frontend, part of shop-web.
- Cents — the smallest unit of a currency. For currencies without cents we still use cents (x100).
